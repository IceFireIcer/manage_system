## 1. 需求背景

### 1.1 从"功能可用"到"真实班级可用"

系统已具备可演示的完整主链路：四张业务表、登录与三角色鉴权、耗材建档、领用整单原子扣减、全量红冲、单次补货入库、三级补货建议与规则模板降级。按原 PRD 的功能蓝图衡量，主要页面与接口已经成形。

但 2026-11-27 的审评以 `main@1c1fe4c` 为基线，核对了八个业务页面、登录与异常页、24 个业务与健康检查端点、四张业务表、规则、迁移、CI 与部署定义，共列出 **109 项发现**。这些发现集中在四个会直接破坏真实教学使用的断点：

- **实际到货没有普遍可用的登记入口**（D01）。网页只能从补货建议卡片进入入库；安全线为零、库存尚充足但已实际到货、借入转入或人工补货时，班委没有入口可记。
- **分批到货被显示为已全部处置**（D02）。库存 0、安全线 10、实到 2 时，页面仍可能移除卡片并提示"本次建议已全部处置"。
- **断网重试可能重复记库存**（C01）。领用与入库都缺跨请求防重和结果查证，超时、页面重载或换人重试会产生第二笔变动。
- **库存审计显示一致，账面余额却已偏离**（F01）。审计只比对流水内部快照，未把最终余额与当前库存对齐，也没有可靠的事件执行顺序（F02、F03）。

这四类问题不是界面瑕疵，而是**账本契约缺失**：系统没有统一的库存事件、单据、业务时间与入账时间、请求标识和证据状态。继续按页面逐个修补，会在盘点、退库、入库纠错等新增路径上重复出现同类缺陷。

### 1.2 为什么需要一份补充 PRD

原 PRD 定义的是目标态功能，SPEC 定义的是接口与规则细节，二者都没有完整回答以下产品级问题：

- 一笔库存变动的最小可信记录是什么，期初、领用、红冲、入库、盘点调整如何共用同一套前后余额与执行顺序？
- 一次领用或一次到货的"单据"是什么，回执、日志、导出如何引用同一个稳定编号？
- 提交结果未知时，用户看到什么状态，系统如何证明"只入账一次"？
- 历史单位、历史名称、历史人员如何在档案变化后仍按发生时语义展示？
- 部分到货、待到货、风险解除等协作状态如何表达，谁来跟进？
- 盘点、退库、报损、入库纠错这些反向变动，与红冲是什么关系？

本补充 PRD 把这些缺口收敛为 **54 项可验收需求**，按八个业务能力域组织，并给出 P0 到 P3 的实施索引。它不是新的功能愿景，而是对原 PRD 的**工程化补全与范围修订**。

### 1.3 审评结论摘要

| 维度 | 结论 |
|---|---|
| 已具备 | 登录与三角色鉴权、档案维护、领用整单原子扣减、全量红冲、单次入库、三级补货规则、操作日志、CSV 基础导出、Docker 部署与 CI |
| 主要缺口 | 统一库存事件与执行顺序、单据与回执、跨请求防重、盘点与退库、部分到货协作、历史单位快照、对账闭环、正式环境安全与恢复 |
| 缺陷密度 | 109 项发现中，P0 11 项、P1 68 项、P2 27 项、P3 3 项；归并后为 54 项待办 |
| 归并原则 | 同一根因、同一实现边界、同一验收场景的发现合并为一项待办；每项保留全部来源编号 |
| 结论 | 演示可用，真实班级使用前必须先完成 P0；P1 决定日常流程是否顺畅；P2/P3 按场景立项 |

## 2. 目标与价值

### 2.1 总体目标

在**不推翻现有技术栈与主链路**的前提下，把系统从"可演示"提升到"单班真实教学可长期使用"，并保证每一笔库存变动都可追溯、可查证、可恢复。

### 2.2 可度量目标

- **账本一致**：任一耗材满足"可信期初 + 全部库存事件变动量 = 当前库存"，对账一致率 100%；不一致时必须显示差量与受影响区间。
- **防重可靠**：同一业务请求在网络重试、页面重载、换人重试下只入账一次，重复入账事件为 0。
- **来源可追**：每笔库存变动都能定位到唯一来源单据与经办人，可追溯率 100%。
- **单位不失真**：历史领用、汇总、审计与导出按发生时单位展示，历史单位错配为 0。
- **差异可闭合**：盘盈、盘亏、退库、报损、入库纠错均产生有依据的反向变动，账实差异闭环率 100%。
- **部分到货可解释**：部分收货后，入库数量与剩余缺口分别显示，残余缺口按最新库存重算。
- **安全可上线**：正式环境强制 HTTPS 与有效密钥，缺失或占位配置拒绝启动。
- **可恢复**：能从独立备份在隔离库恢复出可登录、可核对的系统，并记录恢复时间与可接受丢失量。
- **验收可复核**：三角色端到端路径、真实 MySQL 并发、弱网与部分到货场景均留存证据。

### 2.3 价值

- **对实训教师**：课前看到的风险可直接下钻到建议或档案，缺货不再因为"没有建议卡片"而被忽略；补货进度对多人可见。
- **对班委**：无建议也能登记实际到货；分批到货不再被误判为完成；盘点、退库、报损有正当入口，不必用"撤销"代替实物操作。
- **对实训学生**：领用结果可查证，断网重试不会重复扣库存；本人历史可按发生时单位查看，错领可发起纠错。
- **对教学管理**：学期交接、历史查询、导出与对账使用同一口径，班委换届有可签收的截止点。
- **对工程交付**：54 项需求与审评编号一一对应，P0/P1/P2/P3 边界清晰，可直接转为任务、测试用例与发布门禁。

## 3. 术语与角色定义

### 3.1 沿用术语

原 PRD 与 `GLOSSARY.md` 中的角色、耗材档案、当前库存、安全库存线、库存缺口、领用流水、红冲流水、净消耗、补货建议、判断依据、巡检、建议处置、操作日志等定义继续有效。

### 3.2 本文件新增或收紧的术语

| 术语 | 定义 |
|---|---|
| 库存事件（Inventory Event） | 一次可审计的库存数量变化。期初、领用、红冲、入库、退库、报损、盘点调整、入库纠错都必须是库存事件，不允许直接改写当前库存。 |
| 执行序号（Execution Sequence） | 同一耗材下单调、唯一的事件顺序号，用于确定"先发生哪一笔"，与业务时间无关。 |
| 业务时间（Business Time） | 业务实际发生的日期时间，例如学生实际领用的时刻、货物实际到达的日期。允许补录。 |
| 入账时间（Posted Time） | 该事件写入系统并改变账面库存的时刻。业务时间可以早于入账时间。 |
| 证据状态（Evidence Status） | 一笔事件或一段账目的可验证程度：可信、证据不足、无法验证。旧数据无法还原顺序或期初时必须显式标注，不得默认"一致"。 |
| 请求标识（Request Key） | 由客户端生成、可复用的业务请求唯一标识，用于识别重试并返回原结果。 |
| 单据（Document） | 一次业务操作的稳定凭证，如领用单、入库单、盘点单、退库/报损单、调整单。单据有稳定编号，可关联一行或多行库存事件。 |
| 处置状态（Disposition Status） | 补货建议的协作状态：待跟进、待到货、部分到货、风险解除。 |
| 期间（Period） | 可结账、可签收的时间区间，用于学期交接与跨期纠错。本期不建"学期"实体，期间由起止时间与状态描述。 |
| 单位快照（Unit Snapshot） | 事件发生时耗材的名称、规格、单位副本，用于历史展示与导出，不随档案后续修改而改变。 |
| 降级（Fallback） | 大模型不可用、超时或输出与结构化结果不符时，回退到规则模板文案。 |

### 3.3 角色与权限边界

| 角色 | 本补充 PRD 明确的边界 |
|---|---|
| 实训教师 | 查看库存、建议、消耗、日志与授权范围内记录；可红冲授权范围内领用；**不执行入库、退库、报损、盘点过账**。 |
| 班委 / 耗材管理员 | 维护档案、管理学生、执行领用、入库、退库、报损、盘点录入与建议处置；不能开通教师或恢复管理员。 |
| 实训学生 | 提交本人领用、查看库存与本人记录、对本人记录发起纠错申请；不能直接红冲，不能执行任何库存写入以外的管理操作。 |
| 校方授权人 / 维护者 | 执行教师开通、班委交接、管理员恢复、备份恢复与密钥轮换；每次操作记录执行人、时间与结果。 |
| 系统运维 | 只处理部署、健康检查、备份、日志与凭据，不参与业务录入。 |

> 原 PRD 的三角色权限矩阵继续有效。本文件新增的"校方授权人/维护者"不是业务页面角色，而是受控运维身份；其操作必须留痕，且不能借开通或恢复流程扩大教师、班委权限。

## 4. 适用范围与范围修订

### 4.1 适用范围

- **业务范围**：单班级实训课耗材管理，覆盖档案、领用、收货、盘点、纠错、退库、补货建议、对账、历史查询、导出与运行交付。
- **数据范围**：单班默认数据空间；数据模型保留 `class_id`，但本期不提供多班级切换界面。
- **终端范围**：PC 浏览器为主，移动浏览器完成领用与查证等高频任务；不要求原生 App。
- **覆盖条目**：本文件覆盖 P0 至 P3 全部 54 项。P2/P3 为"场景触发项"，未确认场景前不进入开发承诺。

### 4.2 对原 PRD 非目标的受控修订

原 PRD 第 5 节列出的部分非目标，经真实班级使用审评后需要升级或收紧。**这是本补充 PRD 与原 PRD 的主要差异，必须经业务方确认后同步修订原 PRD 或新增 ADR。**

| 原 PRD 非目标 | 本补充 PRD 的处置 | 依据 |
|---|---|---|
| 不做数据备份、容灾与生产级高可用 | **升级为 P0 最低可恢复机制**：周期备份、独立副本、隔离恢复演练；仍不做高可用与自动容灾 | J05 / P0-09 |
| 公网 HTTP 直接访问 | **正式环境必须 HTTPS 与 Secure Cookie**；演示环境可保留 HTTP，但必须与正式环境隔离并明确标识 | J01、J02 / P0-08 |
| 不做密码找回、自助注册 | 仍不做自助找回与自助注册；**新增班委受控重置学生密码、校方授权人恢复管理员** | A02、A03 / P0-07、P1-05 |
| 不做登录失败锁定、验证码 | 仍不做账号锁定与验证码；**新增适度登录节流与认证日志容量保护** | J04 / P1-25 |
| "提醒"仅指页面预警与建议卡片 | **新增站内待办提醒**（P1-18）；外部推送（邮件/短信/微信/App）仍排除 | D07 / P1-18 |
| 不做多班级管理界面 | 仍不做多班级界面；**新增单班防混入校验**；多班级隔离需单独立项 | I05 / P2-11 |
| 不做批次、保质期、条码、包装规格 | 保持 P2/P3 场景项，确有分装或有效期需求时再立项 | B11 / P2-03 |
| 不做采购、供应商、扫码、硬件、客户端 | 保持 P3，需校方明确设备、采购职责与维护条件 | K04、K05 / P3-02、P3-03 |
| 不做跨学期结转与账务自动化 | 仍不做自动结转；**新增学期交接、结账与期间调整的最小记录** | K02 / P2-05 |
| 不设计多级审批流 | 仍不做普通耗材审批；**特殊耗材的预留/限额仅为 P2 场景项** | K01 / P2-04 |

### 4.3 仍不在本文件范围

- 外部推送渠道、自助注册、学生自助找回密码、第三方身份登录。
- 生产级高可用、多活、自动容灾、跨地域备份。
- 原生 App、小程序、扫码枪、RFID、电子秤等终端与硬件。
- 自动采购下单、供应商结算、财务记账、发票与成本核算。
- 多班级管理界面、班级切换、多租户。
- 由 AI 自动执行红冲、入库、盘点过账等库存写操作；AI 只输出建议与解释。

### 5.3 优先级口径

| 级别 | 判定 | 本文件的完成含义 |
|---|---|---|
| P0 | 使用真实账号与真实库存前的阻断项 | 不同时满足不得开放真实班级使用；含备份恢复核验与真实 MySQL 并发验收 |
| P1 | 典型教学流程会被中断、结果会误导或产生明显人工对账负担 | 目标是在一个完整学期内不依赖纸笔兜底 |
| P2 | 按业务量、场景或管理范围补齐的能力 | 需场景确认与单独立项，不作为默认承诺 |
| P3 | 当前单班 Web 场景的可选扩展 | 有设备、采购职责或个性化需求时再评估 |

### 5.4 统一需求原则

以下原则适用于全部 54 项，不再逐条重复：

1. **库存只经事件变化**：任何写操作不得直接 `UPDATE` 当前库存而不留库存事件。
2. **先单据后流水**：一次业务操作先取得稳定单据编号，再写库存事件；回执、日志、导出引用同一编号。
3. **双时间并存**：每笔事件同时记录业务时间与入账时间，查询必须说明使用哪一个。
4. **证据不足要显式**：旧数据无法确认期初、顺序、单位或来源时，显示"证据不足/无法验证"，不得默认为一致。
5. **写操作可重试**：所有库存写入接受请求标识；同一标识只产生一次业务结果。
6. **档案变化不改写历史**：历史展示使用发生时快照；单位变更走新档案或受控换算。
7. **权限在接口层落实**：页面隐藏不算权限；每个直接请求都必须校验对象范围与字段范围。
8. **降级不改变数字**：模型、缓存、网络失败只能改变文案与时间标识，不得改变规则计算的分级与数量。

## 6. 功能需求（按业务域）

### FR-S1 账号、身份与共享终端安全

**域目标**：让真实账号可安全开通、交接、更正与退出，并保证共享设备、多个标签页和停用账号不会造成身份错用或历史断链。

**域边界**：包含教师开通、班委交接、管理员恢复、首登改密、会话撤销、学生密码重置、花名册导入、人员更正、数据权限、单班隔离。不包含自助注册、自助找回、第三方登录与多班级界面。

#### FR-S1-01 首次启用、改密与服务端会话失效

- **优先级**：P0　**来源**：P0-06（审评 A01、A05）
- **需求**：首次凭据一次性交付，首次登录引导并强制改密；改密、停用、重新启用、退出必须在服务端使相关会话失效，区分"退出当前会话"与"撤销全部会话"；认证审计只记录脱敏信息，不得在部署日志输出明文初始密码。
- **验收**：首登改密后初始凭据与旧会话失效；停用再启用后旧会话仍失效；公共设备退出后受保护页面要求重新登录；部署日志无明文初始密码。

#### FR-S1-02 教师开通、班委交接及管理员恢复

- **优先级**：P0　**来源**：P0-07（审评 A03、J07）
- **需求**：提供空库与现有库的受控教师开通、班委交接和管理员恢复入口，由校方授权角色或运维命令执行，记录执行人、时间与结果；自举失败时必须显示"需初始化"或"需恢复"状态，不得以可登录页面掩盖无管理员状态。
- **验收**：空库能登入教师、班委、学生三个角色；已有班委时仍可开通教师；自定义管理员账号可恢复；教师或普通班委不能借开通流程扩大权限。

#### FR-S1-03 共享设备会话、可恢复草稿和课间快填

- **优先级**：P1　**来源**：P1-04（审评 A06、A12、C04）
- **需求**：同站点标签页同步退出与换号状态，旧会话发起的请求必须丢弃；会话临近过期时提示；短时保存同一用户未提交的领用草稿与待查证请求；允许复用最近明细，但在提交前重新核对库存、业务时间与领用人。
- **验收**：一页换到另一账号后，旧页及时锁定且不能以新身份发送旧草稿；同一学生重新登录可恢复待填写内容；提交前重新核对库存与领用人；另一标签退出后旧页敏感区立即锁定。

#### FR-S1-04 人员更正、学生密码重置和历史人员筛选

- **优先级**：P1　**来源**：P1-05（审评 A02、A04、A10、A11）
- **需求**：授权人员按稳定用户 ID 更正姓名或学号，代登记选项显示可区分同名人员的标识；通过受控临时凭据重置学生密码，统一输入长度、账号规范与并发冲突反馈；历史查询与日志筛选可选择停用人员，但代登记只能选择当前可用人员。
- **验收**：改名后历史仍归属同一用户；历史筛选可定位停用学生，代领新单拒绝选择停用学生；同名人员可区分；并发重复创建同一账号返回可理解结果；重置后旧凭据失效。

#### FR-S1-05 接口层落实学生与教师数据权限

- **优先级**：P1　**来源**：P1-06（审评 A07、A08）
- **需求**：按实际职责确认学生可见的总览字段，以及教师可查看、导出、红冲的对象范围；敏感登录审计与一般教学记录分别授权；所有接口按最小必要字段返回，页面隐藏不能替代接口校验。
- **验收**：覆盖三角色的页面路径与直接请求；学生只取得授权库存数据及本人记录，不返回班级汇总指标；教师访问范围内记录可正常办理，越权请求被拒且不回传多余字段。

#### FR-S1-06 花名册预览导入与离班处理

- **优先级**：P1　**来源**：P1-07（审评 A09）
- **需求**：提供名单模板、批量预检、同名与重复账号处理、导入批次回执；离班使用停用或归档，保留必要历史与授权，禁止物理删除造成审计断链。
- **验收**：部分重复或格式错误的名单可逐行定位；确认导入后结果可查；同一批次重试不会重复建号；已离班学生历史按权限可查。

#### FR-S1-07 个人资料、账号归档与数据留存规则

- **优先级**：P2　**来源**：P2-01（审评 A13、K06）
- **需求**：按实际身份管理流程提供资料核对与账号详情；确定教学、管理、运维角色可见的身份字段，以及毕业离班、到期归档和最小化导出规则；学校已有制度时直接采用。
- **验收**：学生能核对本人资料；归档后仍能按权限查到必要历史；个人数据的页面、报表与 CSV 使用同一可见范围。

#### FR-S1-08 单班校验与多班级隔离方案

- **优先级**：P2　**来源**：P2-11（审评 I05）
- **需求**：单班导入时检查班级归属，禁止第二班数据误混入；若正式管理多班，先确定班级成员与任课教师权限，并覆盖库存、领用、巡检、日志、导出和缓存隔离。
- **验收**：单班实例不会意外混入第二班数据；启用多班功能的实例可用两班样本分别验证查询、写入、链接与导出；多班级界面需另行修订 SPEC 范围。

### FR-S2 耗材档案与库存账本

**域目标**：建立唯一可信的库存账本，使期初、领用、红冲、入库、盘点调整等全部变动遵循同一事件契约，并保护历史单位与档案语义。

**域边界**：包含库存事件、执行顺序、前后余额、单位快照、期初核对、档案编码与导入、停用与复启、风险总览、分柜与批次。不包含采购、供应商与财务成本。

#### FR-S2-01 统一库存变动与执行顺序

- **优先级**：P0　**来源**：P0-01（审评 F02、F03、I01、I02、I08）
- **需求**：把期初、领用、红冲、入库接入同一库存变动逻辑。一次事务记录变动量、变动前后库存、耗材级执行顺序、业务时间、实际入账时间、来源单号和经办人；用数据库约束保护库存下限、流水类型与状态组合、红冲原单外键和一单一红冲关系；迁移前扫描异常旧数据，保留旧流水与日志。
- **验收**：期初 5、入库 5、领用 3 时，账本依次为 5、10、7；同一耗材并发领用、红冲或入库时，每笔变动前后值与实际变动量相符，任一写入失败整笔回滚；无法还原的旧事件标记为"证据不足"；先入后领与重复余额场景顺序正确。

#### FR-S2-02 核对期初、流水与当前库存

- **优先级**：P0　**来源**：P0-02（审评 F01、F04）
- **需求**：同时核对可信期初、各步库存与数据库当前库存；余额不符时显示差量；缺期初、无事件或来源解析失败时显示证据状态，并标出受影响的事件或区间；期初来源、日志解析缺口与首笔之后校验分别展示。
- **验收**：流水末值 7、当前库存 9 时显示差异 2；缺可信期初或有无法读取的事件时显示"无法验证"及所在区间；合法的先入后领显示一致；被跳过的事件可列出处理状态。

#### FR-S2-03 保护计量单位与历史档案

- **优先级**：P0　**来源**：P0-04（审评 B03）
- **需求**：有余额或历史流水时保留原基础单位并限制直接改写；历史名称、规格、单位使用发生时快照或可核实的档案版本；单位确需变更时定义新档案或受控换算，保留旧单位、换算依据与来源。
- **验收**：历史领用 10 个，未来按盒建档后仍显示 10 个；页面、CSV 和审计读取同一历史字段；旧数据无法确认单位时显示"待核对"；单位变更不改写既有事件。

#### FR-S2-04 耗材编码、期初台账导入与实例核对

- **优先级**：P1　**来源**：P1-08（审评 B01、B02）
- **需求**：确定稳定耗材标识和同班同规格的判重规则；新增数据库唯一约束前检查旧重复；提供纸质台账导入的预览、初始计数时点、来源记录和失败明细；同名不同规格允许按业务规则共存。
- **验收**：同名不同规格可按已选规则识别，真正的同一档案并发创建只成功一次；纸质台账导入后可逐行与期初库存对账；导入结果可复核总类数与分单位数量。

#### FR-S2-05 停用余量、复启及并发编辑冲突

- **优先级**：P1　**来源**：P1-09（审评 B04、I04）
- **需求**：停用前显示余量、待收货及待处理事项并保存停用原因；复启时核对余额；档案和账号状态被并发修改时提供冲突提示，并记录确切前后值；明确"已开始登记"与"已停用"相遇时的最终允许行为。
- **验收**：有余量耗材停用后仍能按权限查账；关联原领用红冲后的回加可见；两位班委用旧数据更新同一档案时，晚提交者收到重新核对提示；停用原因与操作人可追溯。

#### FR-S2-06 课前风险总览、缺货跳转与写后刷新

- **优先级**：P1　**来源**：P1-10（审评 B07、B08、H02）
- **需求**：统一库存总览的缺货优先规则；显示安全库存线为零但缺货的耗材及预警配置覆盖情况；教师可从风险耗材直达相关建议或档案；入库、红冲、领用后刷新受影响数据，较旧响应不得覆盖新库存。
- **验收**：安全线为零且缺货的耗材排在有库存预警项之前；轮询失败保留带时间的旧结果与重试入口；旧请求晚返回时页面仍显示刚确认的状态；总览与服务端排序口径一致。

#### FR-S2-07 档案分类、柜位、停用维护与批量设置

- **优先级**：P2　**来源**：P2-02（审评 B05、B06、B09）
- **需求**：按实际物料规模提供分类、受控柜位、规格或别名检索；教师只读查看授权档案，班委可查全部、停用原因与更新时间；按需支持批量启停、安全线预览、清单导出与货架标签。
- **验收**：批量设置前可核对影响范围，提交后有逐项回执；教师可浏览授权的历史档案；班委可更正停用档案的非库存字段；总览"总类数"只计启用项。

#### FR-S2-08 可归还物品、拆包精度与批次有效期

- **优先级**：P2　**来源**：P2-03（审评 B10、B11）
- **需求**：同场管理耐用工具时，补充借出、归还、损坏与责任状态；确有分装或有效期要求时，设计最小单位、换算精度、批次、到期与可用量，不混合不同单位直接求和。
- **验收**：借出、归还和损坏可复核；拆包、分装或批次退出后库存与流水仍按单位守恒；界面明确当前适用的耗材类别与精度规则。

#### FR-S2-09 分柜库存和仓位调拨

- **优先级**：P2　**来源**：P2-14（审评 K03）
- **需求**：确实存在多实训室或多柜位时，区分各位置可领库存、调拨记录与在途数量；明确转出、收货、取消及盘点规则，调拨前后总量守恒。
- **验收**：一笔跨柜调拨能查到来源和去向；调拨后总量守恒；学生能查各位置实际可领数量；在途数量不计为可领库存。

### FR-S3 领用、纠错与退库

**域目标**：把一次领用变成有单号、有回执、可防重、可查证、可纠错、可退库的完整业务，而不是若干条互不关联的流水。

**域边界**：包含领用提交、回执、补录、红冲、重登、退库、报损、批量纠错、弱网草稿与集中发放。不包含审批流与采购。

#### FR-S3-01 领用与入库防重及提交结果查证

- **优先级**：P0　**来源**：P0-03（审评 C01、C03）
- **需求**：写入使用可复用的请求标识，按主体、操作和参数识别重试；落账与回执关联保存；请求超时、断网或 5xx 时保留查证状态，支持重开页面后查询"处理中、已提交、已拒绝"；撤销重复请求可查到既有红冲，重复标识但内容改变时给出冲突。
- **验收**：首次提交已入账但响应丢失，重发同一请求只产生一笔变动并返回原回执；不同真实领用仍可分别入账；刷新、返回、改表单、再次确认和换标签页后仍可查回原结果；失败整笔回滚。

#### FR-S3-02 领用单、回执、选项恢复与错误定位

- **优先级**：P1　**来源**：P1-02（审评 C02、C06、C11、H01）
- **需求**：为一次领用保存稳定单号和逐行流水 ID；回执直达本单，展示领用人、经办人、业务时间、入账时间及单位；统一重复耗材、库存不足和停用错误，按字段路径与行 ID 定位；重试读取后恢复预选项与有效填写。
- **验收**：一次领用三行可从回执与日志分别打开所有明细；新单按 SPEC v1.1 校验不同耗材，历史分行仍可查；部分行库存不足时整单回滚，界面定位到准确行与原因；回执、打印与下载使用同一数据。

#### FR-S3-03 补录与盘点后的入账口径

- **优先级**：P1　**来源**：P1-03（审评 C05）
- **需求**：录入区同时展示业务时间、实际入账时间与经办人；记录补录原因；定义"已计入期初"或"已盘点"的旧单如何关联凭证与调整；按业务决定超期纠错的权限和入口，明确普通补录的允许区间。
- **验收**：盘点前发生、盘点后补登的同一领用只影响一次库存；允许区间内的补录可正常办理，超出区间有明确正确路径；补录原因与责任人可追溯。

#### FR-S3-04 实物退库、部分归还和报损

- **优先级**：P1　**来源**：P1-14（审评 C09）
- **需求**：明确实物退库、残损报废和登记纠错三种操作的权限、可用数量变化及来源凭证；按实收且可复用的数量增加可用库存，并保存对应领用或盘点记录；退库与红冲必须区分，不得用撤销代替实物归还。
- **验收**：领用 10 个、只退 2 个时按实际可用情况回加相应数量；报损审核有原因与库存影响；按原流水红冲时仍能查到关联证据；退库数量不得超过可退数量。

#### FR-S3-05 学生报错、教师红冲和关联重登

- **优先级**：P1　**来源**：P1-15（审评 C08）
- **需求**：允许学生从本人记录提交纠错，教师从具体详情处理；红冲可录备注并展示关联重登；保留原流水、原因、经办人和处理结果，禁止学生直接执行红冲。
- **验收**：学生报错后能看到处理状态，不能直接执行红冲；教师进入详情可核对原单；红冲与重登分别有单号并可互相追溯；误操作的重登不覆盖原记录。

#### FR-S3-06 集中班组领用与特殊耗材预留

- **优先级**：P2　**来源**：P2-04（审评 C07、K01）
- **需求**：根据课间发放规模确定可配置的明细数、分组分发和份额；确需限额或先确认的耗材，再定义申请、预留、领取、未取释放的例外流程；普通耗材保留即领即扣。
- **验收**：集中给多人发放后能对回单据与每人领取记录；特殊耗材预留到期后可重新领取，已领取数量只入账一次；调整明细上限需同步修订 SPEC。

#### FR-S3-07 学期交接、结账和批量红冲

- **优先级**：P2　**来源**：P2-05（审评 C10、K02）
- **需求**：保存期初、期末与签收人，定义已结账期间的调整方式；选定多行红冲的处理方式、确认范围和结果追溯；已签收期间的更正必须产生单独依据，不得静默改写历史。
- **验收**：历史期末结余可按同一版本复核；跨期纠错保留关联凭证；批量红冲能明确显示各行结果及库存影响；交接记录可签收、可查询。

#### FR-S3-08 弱网草稿与临时停机回录

- **优先级**：P2　**来源**：P2-10（审评 H05）
- **需求**：设计可标注时点的只读缓存、待提交草稿和纸质临时登记回录；网络恢复后重新校验身份、库存与业务项，关联唯一凭证后入账，禁止自动重放写操作。
- **验收**：离线数据明确标注时点；联机后能检索待录项目并逐笔确认；重复回录能查见原结果；恢复后入账不会产生第二笔库存变动。

### FR-S4 收货、盘点与补货协作

**域目标**：让"实际到货、分批到货、盘点差异、补货跟进"成为可登记、可协作、可解释的闭环，不再依赖建议卡片是否出现。

**域边界**：包含无建议收货、入库单与纠错、建议处置状态、盘点与过账、补货规则修正、巡检可信度、站内待办、课表与预计到货、巡检容量。不包含采购下单、供应商、物流与外部推送。

#### FR-S4-01 无建议的实际到货登记

- **优先级**：P0　**来源**：P0-05（审评 D01）
- **需求**：从库存总览或耗材档案提供收货入口，复用同一入库流程；班委确认实收数量后入账并取得单号；停用耗材按已有权限提示处理；教师和学生的入库写操作由后端拒绝。该需求需要修订 ADR-0002 "建议处置为唯一入口"的决策。
- **验收**：安全库存线为零或库存充足的启用耗材也能登记实际到货，每笔可按单号查回入库量与库存结果；无建议收货与建议收货使用同一单据与事件契约；教师和学生直接请求入库被拒。

#### FR-S4-02 入库流水查询、收货凭证和入库纠错

- **优先级**：P1　**来源**：P1-11（审评 D04、D05）
- **需求**：提供独立入库单查询，记录实收日期、实际数量、单位、来源和经办人；支持多行到货、部分收货与按原单纠错；提交有回执和逐行结果；入库纠错使用关联反向事件，不直接覆盖当前库存。
- **验收**：同一到货批次可追溯每行；发现录错数量时按原单写纠错记录并核对可扣回数量；入库回执与库存、操作日志相符；历史补登明确标注业务时间与入账时间。

#### FR-S4-03 补货建议处置、部分到货与协作状态

- **优先级**：P1　**来源**：P1-12（审评 D02、D03）
- **需求**：保存建议对应的处理人、状态和关联入库单，区分待跟进、待到货、部分到货与风险解除；成功收货后按当前库存重算残余缺口；其他教师或班委能看到处理进度；更新 ADR-0002 的状态语义。
- **验收**：库存 0、安全线 10、实到 2 时，入库显示 2 且建议继续显示缺口 8；部分到货不移除卡片，风险解除才标记完成；处理进度与入库单可互相追溯。

#### FR-S4-04 实盘、复盘差异、过账与责任追踪

- **优先级**：P1　**来源**：P1-13（审评 D06）
- **需求**：支持记录盘点时点、系统量、实盘量、差异和原因，保存盘点人、复核人及过账结果；定义盘点期间领用和红冲如何纳入差异计算；同一盘点单重复提交只生成一次调整。
- **验收**：同一耗材实盘短缺或盘盈均有可追溯调整记录；盘点期间有并发变动时可核对正确基准；同一盘点单重复过账只生成一次调整；调整关联原盘点单与证据。

#### FR-S4-05 修正补货规则并在建议页说明

- **优先级**：P1　**来源**：P1-16（审评 E01、E02、E03、E04）
- **需求**：划分互不重叠的两段七天窗口；按整数缺口和净耗计算固定七天建议量，避免浮点取整多一单位；输出每项命中原因；页面展示三级阈值、公式、跳过条件和规则版本，规则说明与后端同源。
- **验收**：分界点 00:00 的记录只计一次；近七天净耗 29、无缺口时建议为 29；库存高于安全线但只够 1 天且趋势持平时，理由明确标注"支撑天数触发"；无数据、净额为零与领用被红冲三种情况文案可区分。

#### FR-S4-06 巡检缓存、生成时间与理由可信度

- **优先级**：P1　**来源**：P1-17（审评 E06、E07、E08）
- **需求**：建议缓存绑定库存版本或失效代次，合并重复计算并丢弃变更前开始的慢结果；返回每项数据时点与理由来源；校验模型解释与结构化结果，失败时回退规则模板；显示来源或降级状态。
- **验收**：模型调用期间发生入库后，旧巡检不能写回旧库存；新旧卡片标注各自时间；模型未配置、调用超时或输出数字与规则结果不符时，都能用一致的规则模板呈现。

#### FR-S4-07 低库存站内提醒与待办确认

- **优先级**：P1　**来源**：P1-18（审评 D07）
- **需求**：定义班委和教师的站内提醒、确认、重新触发与解除；去重同一持续风险，按课前或已发生业务变动触发；站内状态与现有页面预警衔接；外部通知渠道按场景另定。
- **验收**：没人打开建议页时仍能生成应处理的站内待办；持续缺货只产生预期提醒；部分到货保留待办；风险解除后标记完成；提醒不因重复巡检无限增长。

#### FR-S4-08 课表、预计到货和建议用量校准

- **优先级**：P2　**来源**：P2-06（审评 D08、E05）
- **需求**：按课次与班级实际消耗记录补货需求、到货预期与履约人；将交付周期、停课、集中上课和低样本处理作为可解释规则输入；预计到货在实收前不计为可用库存。
- **验收**：下一次课到货不足时可提前发现风险；预计到货在实收前不计为可用库存；规则依据可复核，停课与集中排期可解释。

#### FR-S4-09 建议检索、巡检容量和处置复盘

- **优先级**：P2　**来源**：P2-07（审评 E09、E10）
- **需求**：按数量与成本目标决定批量聚合、巡检预算和单耗材重算；增加按耗材定位、降级结果汇总，以及必要的历史决策输入与实际收货结果；约定复盘记录的保留期限。
- **验收**：大量档案下按目标响应，重复巡检有上限；能查到关键处置当时的规则、预计量和实收量；无变化巡检不生成冗余历史。

### FR-S5 时间、对账、历史与报表

**域目标**：统一"业务时间、入账时间、查询区间"的口径，使库存时点、消耗统计、历史记录与导出可以互相对账，而不是各页面各算一套。

**域边界**：包含业务时区、日期边界、时点库存、来源跳转、日志与状态快照、消耗统计、历史筛选、CSV、报表与查询性能。不包含财务记账与外部 BI。

#### FR-S5-01 业务时区、日期边界与查询报错

- **优先级**：P1　**来源**：P1-01（审评 G01、G02）
- **需求**：服务端明确业务时区（上海业务日）、查询起止和数据时点；页面统一显示业务日；接口校验反向区间，日期筛选采用左闭右开；明确带偏移的补录输入如何归一；今日指标只计已确认的业务日与状态范围。
- **验收**：同一数据在不同设备时区显示同一业务日；午夜、结束日最后一秒、反序区间和带偏移补录均有正确结果；记录页与日志页对反序输入给出一致提示。

#### FR-S5-02 库存时点、来源跳转与对账反馈

- **优先级**：P1　**来源**：P1-19（审评 F05、F06、F07）
- **需求**：明确"按入账时间查询的当时账面库存"；对补录场景提供"按业务时间重排"的单独口径并标注依据；逐条打开期初、领用、红冲和入库来源；修复旧请求覆盖与空时点展示；审计标记提供差异值、首次异常与复核处置状态。
- **验收**：上午正常领用、下午补录更早事件时，按实际入账时点查询的库存正确；两种口径明确标识；每条可识别事件能直达精确来源，切换耗材不会串数据；早于首事件或晚于当前时点显示正确空态。

#### FR-S5-03 操作日志筛选、状态快照及受控导出

- **优先级**：P1　**来源**：P1-20（审评 F08、F09、F10）
- **需求**：兼容账号启停日志的旧字符串快照，保存发生时必要的经办人与对象标识；支持按目标类型与 ID、动作、结果、经办人和日期检索；记录导出、重要权限变更与运维改动；定义敏感事件可见范围及留存方式。
- **验收**：旧日志能正确显示启停状态变化；按指定耗材、停用经办人或单据号可找到记录；授权导出经过审计，教学角色只看到授权字段；新增事件不破坏既有日志展示。

#### FR-S5-04 消耗统计区分红冲影响和计量单位

- **优先级**：P1　**来源**：P1-21（审评 G03、G04）
- **需求**：分别展示发出量、红冲量、净额和跨期纠错；明确备料估算按原领用归因的适用范围；数量按单位汇总，接口不输出易被误用的跨单位总量；同级补货排序采用可解释的实际紧迫度。
- **验收**：上一周领用、下一周红冲时，账务净额与备料数据各自可解释；卷、张、支分别显示合计；页面不展示无业务含义的跨单位总数；排序依据可说明。

#### FR-S5-05 历史记录筛选、直达和返回

- **优先级**：P1　**来源**：P1-22（审评 G05、G06、G07）
- **需求**：学生从本人历史可选停用耗材；记录使用稳定 ID 和发生时单位，显示备注；明确"清除全部"与快捷过滤的语义；修复同页 URL 变化、无权详情状态、从抽屉返回后的筛选、页码与焦点恢复。
- **验收**：同一页切换不同流水号时打开正确详情；学生能查本人停用耗材流水；快速清筛选的结果符合按钮含义；组合不可达状态时给出提示；返回后筛选与页码保持。

#### FR-S5-06 完整、安全且可对账的 CSV

- **优先级**：P1　**来源**：P1-23（审评 G08、G09）
- **需求**：显示匹配总数和导出范围，按规模支持分段或异步完整导出；导出带稳定流水号、关联红冲、单位和入账时间；按文本安全处理用户输入，防止表格软件执行公式；按权限限制个人数据字段，并记录导出条件与责任人。
- **验收**：超过一万条时能确认已导出数量与总量，并支持取完整结果；导出与同条件查询一致；常用表格软件按文本打开；导出事件可追溯；无权限字段不出现在文件中。

#### FR-S5-07 自定义报表、下载及打印凭证

- **优先级**：P2　**来源**：P2-08（审评 G10、G12）
- **需求**：支持按区间、课程或学期查询统计；按需提供领用回执、收货凭证、盘点表、耗材清单、日志或报表的下载与打印视图；凭证保留单号、日期、单位、对象和授权范围。
- **验收**：所选区间可下钻到流水，数据与页面、CSV 一致；凭证字段完整；明确区分"无样本"与"净额为零"；打印版不因导出而放开权限。

#### FR-S5-08 常用查询、服务端分页与索引

- **优先级**：P2　**来源**：P2-09（审评 G11、I06）
- **需求**：围绕编号、耗材、经办人、备注和时间设计检索；补充稳定排序、筛选分享与列选项；以真实数据量核验全量列表、查询计划、索引和分页；分享链接只包含允许共享的条件。
- **验收**：在约定数据规模下仍能按目标完成查询；翻页、刷新与分享返回相同筛选范围；历史分页与导出相符；慢查询有可复核的索引或聚合方案。

### FR-S6 课堂可用性、帮助与个性化

**域目标**：保证课间 10 分钟窗口内，手机、键盘、读屏与弱网用户都能完成关键任务，并在遇到账号、耗材或故障问题时找到就近帮助。

**域边界**：包含移动端布局、软键盘、焦点、读屏播报、角色帮助、故障联络与个性化显示。不包含原生 App 与多语言强制要求。

#### FR-S6-01 手机、键盘、读屏和角色帮助

- **优先级**：P1　**来源**：P1-24（审评 H03、H04、H06）
- **需求**：在 320、390 像素及桌面环境验证常用任务，修复软键盘遮挡、弹窗回焦、键盘焦点进入正文和重要状态播报；补充学生与教师首次使用、账号停用及故障联络入口；故障信息携带可复制的请求编号。
- **验收**：在 200% 缩放与键盘操作下可完成登录、领用、追查回执与入库；读屏可取得提交结果与错误；窄屏无横向阻断；班委交接可用同一说明完成。

#### FR-S6-02 语言、主题及个性化浏览

- **优先级**：P3　**来源**：P3-01（审评 H07）
- **需求**：确有夜间、多语言或跨页检索需求时，按现有页面增加语言、主题、全局搜索和常用筛选；现阶段优先落实键盘、对比度与查找阻塞。
- **验收**：用户偏好可持久并按账号使用；切换显示设置后核心页面仍符合本地化、对比度与键盘操作要求；不因个性化引入第二套权限口径。

### FR-S7 工程契约、运行安全与交付

**域目标**：让系统可以安全地承载真实账号与数据，并在升级、故障、迁移和回滚时可定位、可恢复、可复核。

**域边界**：包含 HTTPS、密钥、备份恢复、最小权限、登录节流、健康检查、请求编号、演示数据、镜像门禁、真实 MySQL 并发、共享契约与部署证据。不包含高可用、多活与自动容灾。

#### FR-S7-01 正式环境 HTTPS 与密钥校验

- **优先级**：P0　**来源**：P0-08（审评 J01、J02）
- **需求**：在实际部署入口落实 HTTPS 和 Secure Cookie，校验来源及代理配置；正式环境启动时检查 JWT 和数据库凭据，拒绝缺失或占位配置；准备可核对的密钥轮换步骤及轮换后的会话策略。
- **验收**：正式地址通过 HTTPS 登录；缺少有效生产密钥时明确启动失败；验证登录、退出、Cookie 属性及轮换后会话策略；演示配置与正式配置可区分。

#### FR-S7-02 数据库备份与恢复演练

- **优先级**：P0　**来源**：P0-09（审评 J05）
- **需求**：明确备份周期、保留期、独立副本和失败反馈；保存备份对应的镜像及迁移版本；在隔离库中演练恢复并校对账号、台账、入库和操作日志；升级前取得可读备份并确认回滚版本与数据库兼容。
- **验收**：能从独立备份恢复一份可登录、可核对的系统，记录恢复时间和可接受丢失量；备份失败可触发反馈；回滚不覆盖正式库；已有数据实例在执行关键迁移前完成演练。

#### FR-S7-03 数据库最小权限、凭据轮换与登录节流

- **优先级**：P1　**来源**：P1-25（审评 J03、J04）
- **需求**：分配应用、迁移与备份账号权限，统一可生效的配置项；补充不影响已有数据的凭据轮换步骤；按账号与来源实施适度登录节流和认证日志容量保护；不因节流阻断整班正常登录。
- **验收**：应用账号仅能执行所需操作；数据库换密后现有台账仍可访问；频繁失败登录受到节流，正常整班登录可完成；认证日志有限长与可查范围。

#### FR-S7-04 服务就绪检测与排障信息

- **优先级**：P1　**来源**：P1-26（审评 J06、J11）
- **需求**：分开进程存活和业务就绪，检查数据库、迁移及必要初始化；用请求编号串联页面错误、API、数据库和模型回退；补充业务异常、备份和磁盘观测；健康检查保留在运维入口。
- **验收**：数据库不可用时就绪检测失败，数据库恢复后恢复就绪；班委报告故障时可用请求编号定位；备份失败及异常峰值可以触发运维反馈；静态页可达不再等同于业务就绪。

#### FR-S7-05 复用演示数据与同提交镜像发布

- **优先级**：P1　**来源**：P1-27（审评 J08、J09）
- **需求**：提供隔离演示样例和可重复的三角色验收数据；将 CI 结论与同一提交的两份镜像绑定；提供可查的版本对、升级与回滚记录；正式环境继续按空库启动。
- **验收**：演示环境能复现缺货、低库存、趋势上升；两个镜像齐全且使用同提交测试结果时才标记该版本可部署；演示数据不会进入正式库。

#### FR-S7-06 真实 MySQL 并发与关键浏览器验收

- **优先级**：P1　**来源**：P1-28（审评 J10、I03）
- **需求**：验证相反顺序的多耗材领用、入库与红冲并行、同次提交的回执丢失和重复请求；为三角色留存浏览器登录、弱网、部分到货及库存审计证据；并发用例与 P0-01 至 P0-03 同步建立。
- **验收**：相反顺序更新不留下半单；锁冲突时返回可重试结果，重试同一笔业务只入账一次；浏览器走完真实业务链并能定位每一步的记录；留存可复查的测试证据。

#### FR-S7-07 共享规则、状态、动作和错误契约

- **优先级**：P2　**来源**：P2-12（审评 I07）
- **需求**：建立统一可核对的角色、状态、分页、日期窗口、规则版本和错误字段契约，集中复用映射；保留已发布接口的兼容路径；修改阈值、动作或状态时，页面说明、接口与日志筛选使用同一数据。
- **验收**：修改阈值、动作或状态时，对应页面说明、接口和日志筛选保持一致；旧客户端和既有记录仍按约定处理；契约变更可在一个版本内追溯。

#### FR-S7-08 升级、镜像供应链和部署证据

- **优先级**：P2　**来源**：P2-13（审评 J12、J13）
- **需求**：演练仅重建后端、代理重连、迁移及版本回滚；按实际部署保留镜像、依赖检查和运行证据；若涉及比赛，取得适用的平台要求及验收记录；补齐可复查的镜像风险与资源检查。
- **验收**：版本回滚后前后端与数据库可用，验证镜像来源和依赖记录；正式实例可复核 HTTPS、备份及模型配置；仅重建后端无需人工刷新代理。

## 7. 关键流程 / 交互说明

### 7.1 新学期首次启用与班委交接

1. 运维以正式配置启动空库，系统检查 JWT、数据库凭据与 HTTPS 配置，缺失或占位时拒绝启动。
2. 校方授权人执行教师开通，创建首个教师账号并交付一次性初始凭据。
3. 教师首次登录，系统强制改密；初始凭据与原会话立即失效。
4. 班委账号开通后首次登录改密；教师可查看本班档案与库存，但不执行入库。
5. 学期中交接时，校方授权人停用原班委、开通新班委，记录执行人、时间与结果；原班委历史保留，可按权限查询。
6. 若空库无可用管理员，页面显示"需初始化/需恢复"，健康检查标记未就绪，不以可登录首页掩盖。

**异常分支**：已有班委时仍可开通教师；自定义管理员账号可恢复；开通流程不能把教师或普通班委提升为管理员。

### 7.2 课间领用、断网与结果查证

1. 学生登录后选择耗材与数量，页面显示业务时间、预计入账时间与当前库存。
2. 提交时客户端生成请求标识，随领用明细一次发送。
3. 服务端在单事务内校验库存、停用状态与领用人，写领用单、逐行库存事件与操作日志，返回稳定单号与逐行回执。
4. 若响应丢失或网络中断，页面进入"处理中/待查证"状态，保留请求标识与明细快照。
5. 学生重开页面或重新登录后，可按请求标识查询：已提交则展示原回执，已拒绝则展示原因，处理中则给出稍后查询入口。
6. 同一请求重发只返回原结果，不产生第二笔变动；请求标识相同但内容改变时返回冲突。
7. 教师或班委在记录页按单号打开回执，看到领用人、经办人、业务时间、入账时间、单位与逐行流水 ID。

**异常分支**：库存不足、耗材停用、领用人停用分别提示并定位到具体行；整单任一行失败时全部回滚；旧标签页换号后不能以新身份提交旧草稿。

### 7.3 无建议收货、部分到货与协作处置

1. 班委从库存总览或耗材档案进入收货，不要求存在补货建议。
2. 页面预填建议量仅作参考，班委必须确认实收数量、实收日期、单位与来源。
3. 提交后生成入库单号，写入库存事件与操作日志；库存立即增加。
4. 若该耗材存在补货建议，系统按当前库存重算缺口：实收小于缺口时状态为"部分到货"，建议保留；实收覆盖缺口时状态为"风险解除"。
5. 其他教师或班委在建议页看到处理人、状态与关联入库单，可继续跟进或补收。
6. 发现入库数量录错时，从原入库单发起纠错，生成关联反向事件，不直接覆盖当前库存。

**异常分支**：停用耗材收货按权限提示；教师或学生直接请求入库被拒；重复提交同一请求只生成一张入库单。

### 7.4 盘点、差异过账与历史纠错

1. 班委创建盘点单，记录盘点时点、盘点人与复核人。
2. 系统冻结该时点的系统量快照；盘点期间发生的领用、红冲、入库仍正常入账，但必须可按执行序号纳入差异重算。
3. 班委录入实盘量，系统计算差异并标注原因（漏录、丢失、破损、历史迁移等）。
4. 复核人确认后过账，生成一条或多条盘点调整库存事件；同一盘点单重复过账只生成一次调整。
5. 盘点前发生、盘点后补登的领用，按"是否已计入期初/已盘点"规则关联凭证，确保只影响一次库存。
6. 教师发现历史领用错误时，从详情发起红冲；如需重新登记，生成关联重登单，原单、红冲单与新单互相可追溯。

**异常分支**：盘点期间并发变动使基准变化时，系统提示重新核对并保留盘点时点快照；无法还原的旧账目标注"证据不足"。

### 7.5 对账、导出与历史查询

1. 教师或班委打开库存审计，选择耗材与时点，系统明确标示当前使用的是"按入账时间"还是"按业务时间重排"口径。
2. 审计逐条列出期初、领用、红冲、入库、盘点调整等事件，显示变动量、前后余额、业务时间、入账时间与来源单据。
3. 末值、当前库存与可信期初同时核对；不一致时显示差量、首次异常与受影响区间。
4. 每条事件可直达来源单据；切换耗材时旧请求结果不得覆盖新结果。
5. 历史记录支持停用人员与停用耗材筛选；备注、发生时单位与单号可查。
6. 导出前显示匹配总数与范围；超过单次上限时提示分段或异步导出；CSV 带稳定编号、单位、入账时间与关联红冲，并按文本安全处理。

**异常分支**：日期反序、时点早于首事件、无权详情、导出超时均有明确状态与恢复路径；导出行为写入审计。

### 7.6 数据库升级、备份恢复与回滚

1. 升级前在隔离库完成一次恢复演练，核对账号、台账、入库单与操作日志。
2. 记录当前镜像版本、数据库迁移版本与备份文件位置。
3. 先备份，再执行迁移；迁移失败时停止发布，保留原始证据，不覆盖正式库。
4. 回滚时使用成对的前后端镜像与兼容的数据库版本；若迁移不可逆，按预演步骤恢复备份。
5. 恢复后用受控业务读验证登录、库存查询、领用回执与审计链路。
6. 发布门禁要求同一提交的 CI 结论与两份镜像齐全，才标记可部署。

**异常分支**：数据库不可用时就绪检测失败；备份失败触发运维反馈；仅重建后端时验证代理自动重连。

| 波次 4 | 对账、可用性与交付 | P1-19 至 P1-24、P1-26 至 P1-28 | 对账闭环、导出可核对、三角色验收与发布门禁完成 |

## 9. 业务规则与 ADR 变更

### 9.1 ADR-0002 修订：入库入口与处置状态

**现行决策**：建议处置是唯一的网页入库入口；处置后移除建议卡片。

**本补充 PRD 的修订**：

| 决策点 | 修订后规则 |
|---|---|
| 入库入口 | 建议、库存总览、耗材档案均可发起入库，全部复用同一入库单与库存事件契约 |
| 建议与入库的关系 | 建议是协作线索，不是入库前置条件；无建议也能收货 |
| 部分到货 | 实收数量小于残余缺口时保留建议，状态为"部分到货"，按最新库存重算缺口 |
| 状态语义 | 待跟进 → 待到货 → 部分到货 → 风险解除；风险重新出现时可重新打开 |
| 卡片移除 | 仅在风险解除或授权角色主动关闭时移除，不由"本次入库"隐式触发 |
| 多人协作 | 记录处理人、状态、关联入库单与更新时间，其他角色可见 |

**状态迁移约束**：待跟进可转待到货或风险解除；待到货可转部分到货、风险解除或回到待跟进；部分到货可继续部分到货或风险解除；风险解除为终态，库存再次低于阈值时生成新的处置记录，不复活旧记录。

### 9.2 ADR-0003 扩展：反向变动族

**现行决策**：纠错使用红冲，保留原记录与反向流水，不删除。

**本补充 PRD 的扩展**：把"反向变动"从单一红冲扩展为五类。所有类型都必须保留原记录、记录原因与经办人、关联来源单据，不得直接覆盖历史余额。

| 类型 | 触发场景 | 数量方向 | 数量上限 | 是否计入消耗净额 |
|---|---|---|---|---|
| 纠错红冲 | 原领用登记错误 | 增加库存 | 原领用数量 | 是，抵减发出量 |
| 实物退库 | 学生归还未使用耗材 | 增加库存 | 原领用未使用数量 | 否，单独列示退库量 |
| 报损 | 领用后破损、无法复用 | 不增加可用库存，单独记录损耗 | 原领用数量 | 否，单独列示报损量 |
| 盘点调整 | 实盘与账面差异 | 增加或减少库存 | 以实盘差异为限 | 否，单独列示盘盈盘亏 |
| 入库纠错 | 原入库数量或品种录错 | 减少库存（反向冲销） | 原入库数量，且不得使库存为负 | 否 |

**共同规则**：反向事件必须有来源事件或来源单据；同一来源的累计反向数量不得超过原始数量；红冲仍遵循"一单一红冲"；退库、报损、盘点调整、入库纠错均生成独立单据与库存事件。

### 9.3 新增契约：库存事件、单据与时间

**库存事件最小字段**：

| 字段 | 含义 |
|---|---|
| 事件 ID | 全局唯一、不可复用 |
| 耗材 ID | 指向耗材档案，不随名称变化 |
| 事件类型 | 期初、领用、红冲、入库、退库、报损、盘点调整、入库纠错 |
| 变动量 | 正负整数，基础单位 |
| 变动前余额 / 变动后余额 | 同一事务内写入，与变动量严格相符 |
| 执行序号 | 同一耗材下单调唯一，用于确定顺序 |
| 业务时间 / 入账时间 | 双时间并存，查询必须标明使用哪一个 |
| 来源单据类型 / 单据 ID | 指向领用单、入库单、盘点单等 |
| 经办人 ID / 角色快照 | 发生时身份，不随账号改名变化 |
| 单位快照 | 发生时单位，用于历史展示 |
| 证据状态 | 可信、证据不足、无法验证 |

**单据类型**：领用单、入库单、盘点单、退库单、报损单、调整单。每张单据有稳定编号、类型、状态、经办人、业务时间、入账时间与关联事件列表。

**时间语义**：

- "按入账时间"回答"系统当时账面上是多少"，用于对账与审计。
- "按业务时间重排"回答"如果补录也按实际发生顺序记账，结果是多少"，仅作解释，不替代账面余额。
- 两个口径必须在页面、导出与接口字段名上明确区分，不得共用一个"时点库存"标签。

**证据状态判定**：

- 可信：期初有来源、事件顺序完整、前后余额与当前库存相符。
- 证据不足：旧数据缺少执行序号、期初来源或单位，但可人工核对。
- 无法验证：缺可信期初、事件不可读或余额差量无法归属。

### 9.4 需要业务方确认的规则

| 编号 | 待确认规则 | 影响需求 | 暂定处理 |
|---|---|---|---|
| R-01 | 部分到货后建议保持待办的条件（实收小于缺口即保持，还是允许人工关闭） | P1-12、P1-18 | 实收小于缺口即保持"部分到货" |

## 11. 验收标准

### 11.1 阶段门槛

**P0 关闭门槛（全部满足才可开放真实班级）**

- [ ] 期初、领用、红冲、入库共用同一库存事件契约，执行序号与前后余额可核对。
- [ ] 库存审计同时核对期初、每步变动与当前库存，差异可见。
- [ ] 同一请求重试只入账一次，断网重载后可查回原结果。
- [ ] 有余额或历史流水时，单位与档案快照受保护。
- [ ] 无建议也能登记实际到货，并获得可查单号。
- [ ] 首登改密、教师开通、班委交接、管理员恢复可用且留痕。
- [ ] 正式环境 HTTPS、Secure Cookie 与生产密钥校验生效。
- [ ] 备份可在隔离库恢复，账号、台账、入库与日志可核对。

**P1 关闭门槛**

- [ ] 三角色可在一个完整学期内完成开学、领用、收货、盘点、纠错、退库、查询与导出，无需纸笔兜底。
- [ ] 部分到货、盘点差异、退库与报损均有独立单据与库存影响。
- [ ] 补货规则、建议说明、处置状态与站内待办一致。
- [ ] 历史人员、停用耗材、发生时单位与备注可按权限查到。
- [ ] CSV 完整、可对账、按文本安全打开，导出有审计。
- [ ] 真实 MySQL 并发与关键浏览器路径留存证据。

**P2/P3 立项门槛**

- [ ] 有明确使用场景、责任人与维护条件。
- [ ] 不改变 P0/P1 已冻结的库存事件、单据与权限契约；如需改变，先修订本文件与对应 ADR。
- [ ] 单独验收，不以"主链路可用"替代。

### 11.2 端到端场景验收

| 场景 | 应看到的结果 |
|---|---|
| 学生首次登录后用手机领用，断网再查 | 初始凭据已更新，同次登记只扣一次；可按单号确认结果并查每条明细 |
| 教师查缺料，班委部分收货 | 缺货可定位到建议或档案；无建议也能实际收货；剩余缺口与入库回执一致 |
| 班委盘点，教师纠正历史领用 | 调整与红冲均指向原始证据；能对上期初、每笔变动、当前库存及实盘差异 |
| 班委登记无建议到货并录错数量 | 入库单可查；纠错按原单生成反向事件，可扣回数量受原单约束 |
| 学生归还部分耗材，另一部分报损 | 退库按实收回加可用库存；报损单独记录；两者都不覆盖原领用 |
| 班委换届交接 | 期初、期末与签收人可查；离班账号停用但历史按权限可查 |
| 查历史并导出 | 停用人员及耗材仍可按权限查到；查询与导出字段、单位、区间一致 |
| 多人协作处理同一补货建议 | 处理人、状态与关联入库单可见；部分到货保留待办；风险解除标记完成 |
| 部署、升级及恢复 | 同一版本前后端可登录；备份能在隔离库恢复；数据库失联可从健康状态与日志定位 |
| 模型不可用时的补货建议 | 分级与数量仍由规则决定；文案回退模板；页面标明降级与数据时间 |

### 11.3 测试与证据要求

- 并发用例必须在真实 MySQL 上运行，覆盖相反顺序领用、入库与红冲并行、重复请求、回执丢失。
- 每个 P0 需求至少有一个自动化或可重复的手工验收记录；每个 P1 需求至少有一条端到端路径证据。
- 浏览器验收记录浏览器版本、视口、缩放、键盘与读屏结果。
- 备份恢复记录备份文件位置、镜像与迁移版本、恢复耗时与可接受丢失量。
- 发布记录保留同一提交的 CI 结论、两份镜像标签或 digest、升级与回滚结果。

## 1. 需求背景

班级实训课经常领用焊丝、砂纸、记号笔、电阻、实训导线等耗材，目前完全依靠纸质本子登记。班委和实训老师人工记录库存，经常不清楚还剩多少、谁领走了；临近上课才发现耗材不够，也没有任何自动提醒；盘点时需要逐页翻阅纸质记录，费时且容易漏记、错记，事后无法准确追溯责任。

示例数据（请按实际调研替换）：单个班级一学期约 20 次领用、5 类耗材，领用时间集中在课间 10 分钟窗口内，人工登记排队、统计滞后问题突出。纸质台账还存在本子丢失、字迹不清、库存与流水对不上等风险。

为此，本项目构建一个轻量化 Web 管理系统，解决小班实训耗材的领用登记、库存监控与补货提醒问题；并引入智能补货 Agent，将"库存控制"知识落地为分级补货建议；最终基于华为云 CodeArts 完成代码托管、流水线构建与云端部署，形成可稳定访问、可完整演示的业务闭环。

本项目同时作为参赛作品。赛事要求依托华为云 CodeArts 码道平台完成代码托管、版本管理、CI/CD 流水线发布与项目协同，综合考察系统功能完整性、业务场景贴合度、创新拓展性与软件工程实践能力。本 PRD 的技术范围与验收标准均按赛事要求约束。项目实际实施于 2026-11-27 迁移至 GitHub（见修订说明）。

## 2. 目标与价值

**目标（可度量）：**

- 实现耗材档案线上维护，支持不少于 5 类耗材（焊丝、砂纸、记号笔、电阻、实训导线）建档，档案字段完整率 100%
- 领用登记支持一次提交最多 5 行，整单原子扣减库存并生成流水，每次成功领用必须有且仅有一条对应流水，覆盖率 100%
- 搭建库存总览页面，实时显示剩余数量；低于安全库存的条目 100% 被标记预警，并可快速识别
- 引入智能补货 Agent：按"紧急 / 一般 / 观察"三级输出结构化补货建议与可解释判断依据；大模型不可用时自动降级为规则模板文案
- 建立完整库存闭环：领用、撤销（红冲）、补货入库三类变动全部留痕，库存只减不增的风险被消除
- 基于 GitHub 完成代码托管、版本管理、CI/CD（GitHub Actions）与云端部署，Web 端可稳定访问演示；本地保留零 Docker 的裸机启动方式作为兜底
- 预期成效（示例目标，按实际测算调整）：以单班级一学期约 20 次领用、5 类耗材估算，单次登记时间由约 1 分钟缩短为 10 秒以内，库存盘点由每周人工翻阅改为实时查看，缺料由被动应对转为提前 1 至 3 天预警，登记与盘点耗时预计下降约 50%

**价值：**

- **对实训教师**：实时掌握库存全貌与分级补货建议，课前从容决策，避免"临上课才发现缺料"
- **对班委 / 耗材管理员**：告别纸质本，档案、领用、流水全部线上化，统计零人工；处置建议即完成补货入库
- **对实训学生**：领用登记 10 秒完成，库存透明可查，领用记录可自查
- **对教学本身**：把供应链运营中的库存控制、安全库存、补货决策知识落地到真实班级场景，形成"登记—扣减—巡检—提醒—补货"的功能闭环，区别于普通台账系统
- **可推广性**：数据模型预留班级维度，巡检逻辑与具体班级解耦，后续可迁移至实验室试剂、社团物资等小场景
- **工程实践**：依据赛事要求完成 CodeArts 托管、版本管理、流水线发布与项目协同，形成可复现的 DevOps 交付链路

## 3. 术语与角色定义

**术语定义：**

| 术语 | 定义 |
|---|---|
| 耗材档案 | 一类耗材的静态信息集合：名称、规格、单位、存放位置、安全库存线、当前库存等 |
| 当前库存（C） | 某耗材此刻可领用的数量，只能经领用、撤销、补货入库三类操作变更 |
| 安全库存线（S） | 触发低库存预警的最低库存阈值，为零表示该耗材不参与预警 |
| 领用流水 | 一次领用的不可变记录：谁、何时、领了什么、领了多少、领后剩余 |
| 撤销领用 | 对已登记领用的纠正操作，产生红冲流水，原流水标记为已撤销但保留 |
| 红冲流水 | 撤销产生的反向流水，与撤销原因、操作人一起留痕 |
| 净消耗 | 统计窗口内领用数量减去红冲数量的净值，负值截断为零；Agent 速率与建议均基于净消耗 |
| 补货入库 | 将补货建议落地的操作，录入实际入库数量并增加当前库存 |
| 库存缺口（G） | G = max(S − C, 0) |
| 近 7 天消耗速率（r） | r = 近 7 天净消耗 ÷ 7，单位：件/天 |
| 可支撑天数（D） | D = C ÷ r；速率等于 0 时视为无穷大 |
| 三级补货决策 | 补货建议的紧急程度分级：紧急 / 一般 / 观察 |
| 判断依据 | Agent 给出建议时所引用的数据事实与推理说明（如缺口、速率、可支撑天数） |
| 巡检 | Agent 逐类读取库存与近 7 天流水、计算指标并生成建议的过程 |
| 建议处置 | 班委对补货建议的处理，录入实际入库数量后完成补货入库 |
| 操作日志 | 只增不改的审计记录，覆盖登录、领用、撤销、档案变更与建议处置 |

**角色定义：**

| 角色 | 职责与权限概述 |
|---|---|
| 实训教师 | 查看库存总览、补货建议、近期消耗汇总、操作日志；可查看并撤销全部领用记录；不执行补货入库 |
| 班委 / 耗材管理员 | 维护耗材档案、设定安全库存线、管理学生账号、执行领用登记与补货入库、维护全部记录 |
| 实训学生 | 提交领用登记（锁定本人）、查询库存总览（含安全库存线）、查询本人的领用记录 |

## 4. 适用范围

**业务范围：** 面向班级实训课的耗材管理，覆盖耗材建档、课间领用登记、库存实时查询、低库存预警、近期消耗统计与补货决策等环节，适用于焊丝、砂纸、记号笔、电阻、实训导线等高频领用小件耗材。

**数据范围：** 当前版本以一个演示班级为默认数据空间（单班级约 5–10 类耗材、每学期约 20 次领用）。数据模型保留班级维度（`class_id`，演示数据全部为 1 班），后续可平滑扩展为多班级、多实验室、多物资场景。本期不引入"学期"实体，学期概念仅存在于文档叙述中，统计一律按时间字段过滤。

**技术范围（依据 ADR-0004）：**

- 开发平台：GitHub（代码托管、分支管理、CI/CD、自动化测试与部署、项目协同）；仓库托管于 GitHub（https://github.com/IceFireIcer/manage_system，2026-11-27 由 AtomGit 迁移，见 ADR-0005）
- 前端：Vue 3 + Vite + Element Plus + Pinia + Axios + vue-router 4 + ECharts 5（库存总览 / 领用登记 / 记录查询 / 建议卡片）
- 后端：Python 3.12 + FastAPI + pydantic v2 + uvicorn（单进程）；数据访问 SQLAlchemy 2.0（同步 Session）+ Alembic + PyMySQL；认证 PyJWT + bcrypt，JWT 存 httpOnly Cookie（SameSite=Lax）
- 数据库：MySQL 8.0（`users`、`consumables`、`requisitions`、`operation_logs` 四张业务表）
- AI 能力：规则引擎负责三级决策计算；默认 DeepSeek API（OpenAI 兼容 SDK）经适配层润色判断依据，适配层保留切换华为云盘古的能力
- 测试与质量：pytest + httpx + pytest-cov + ruff（不引入 mypy）
- 部署：云端单台华为云 ECS（2C4G）+ Docker Compose（nginx:alpine + python:3.12-slim + mysql:8.0），公网 IP + HTTP 直接访问；本地开发不启动 Docker，使用已装 Python 3.12.7 / MySQL 8.0.46 / Node 25.4.0 裸机运行
- CI/CD：GitHub Actions 双工作流——`ci.yml`（前端构建 + 后端 pytest + ruff）与 `docker-publish.yml`（构建并推送 GHCR 镜像 `labstock-api` / `labstock-web`），服务器拉取部署；镜像带版本标签，回滚即切换标签

**终端范围：** PC 浏览器为主（Chrome / Edge 最新版），移动端浏览器可正常浏览页面（不要求原生 App）。

**适用场景：** 课前耗材准备、课间领用登记、课后盘点核对、补货决策与答辩演示。

## 5. 非目标（不在本期范围）

- 不包含采购订单、供应商管理、物流跟踪与财务结算功能
- 不集成扫码枪、RFID、电子秤等硬件设备（领用数量手工填写）
- 不开发微信小程序、原生 App 或桌面客户端
- 不设计多级审批流（领用登记即扣减，无需教师逐单审批）
- **不做任何外部推送**（邮件 / 微信 / 短信 / App 通知）；"提醒"仅指库存总览页面预警标记与补货建议卡片
- 不做登录失败锁定、验证码、密码找回、自助注册（账号由初始化脚本与班委用户管理维护）
- 不做数据备份、容灾与生产级高可用（面向单班级小数据量演示场景）
- 不自动处理跨学期的库存结转与折旧对冲（历史数据可查询，但不做跨学期账务自动化）
- 不提供耗材批次、保质期、条码、包装规格管理（列为远期扩展点）
- 不做多班级管理界面、班级切换与班级管理员角色（仅保留 `class_id` 数据维度）

## 6. 功能需求

### FR-1 用户与权限管理

系统采用完整的多角色登录机制，教师、班委/耗材管理员、学生分别登录，按角色控制权限。

- FR-1.1：系统提供登录页，用户以"账号 + 密码"登录；密码以 bcrypt 哈希存储，不得明文存储
- FR-1.2：用户角色固定为三种：教师（teacher）、班委/耗材管理员（admin）、学生（student）；角色决定可见菜单与可执行操作
- FR-1.3：权限矩阵如下（"✓"为允许，"—"为禁止）：

| 功能 | 教师 | 班委/管理员 | 学生 |
|---|---|---|---|
| 查看库存总览与预警 | ✓ | ✓ | ✓ |
| 新增/修改/停用耗材档案 | — | ✓ | — |
| 设定安全库存线 | — | ✓ | — |
| 新增/启停学生账号 | — | ✓ | — |
| 提交领用登记 | ✓ | ✓ | ✓（锁定本人） |
| 撤销领用（红冲） | ✓ | ✓ | — |
| 查看全部领用记录 | ✓ | ✓ | — |
| 查看本人领用记录 | ✓ | ✓ | ✓ |
| 查看补货建议卡片 | ✓ | ✓ | — |
| 处置补货建议（入库） | — | ✓ | — |
| 查看操作日志 | ✓ | ✓ | — |
| 查看近 7/30 天消耗汇总 | ✓ | ✓ | — |

- FR-1.4：未登录访问任何业务页面须跳转登录页；越权接口调用返回 403 并提示"无权限访问"
- FR-1.5：会话保持：JWT 存放于 httpOnly Cookie（SameSite=Lax），有效期 8 小时；提供退出登录并清除会话
- FR-1.6：系统初始化时预置三个演示账号（教师、班委、学生各一），账号密码写入交付说明文档
- FR-1.7：用户表字段（`users`）：`id`、`account`、`password_hash`、`name`、`role`、`class_id`、`status`（启用/禁用）、`created_at`
- FR-1.8：用户管理（仅班委）：可新增学生账号（账号、姓名、初始密码）与启停用学生账号；**不得创建教师或班委账号，不得修改任何用户角色**；教师账号仅由初始化脚本维护
- FR-1.9：被禁用用户无法登录；其历史领用流水与操作日志保留可查

### FR-2 耗材档案管理

- FR-2.1：班委/管理员可新增耗材，必填字段：耗材名称、规格、单位、存放位置、安全库存线、当前库存；校验规则：名称非空且同类不重名，安全库存线与当前库存均为 ≥ 0 的整数；安全库存线为 0 表示该耗材不参与预警
- FR-2.2：支持修改耗材的名称、规格、单位、存放位置、安全库存线；当前库存不提供直接编辑（只能通过领用、撤销、补货入库变更，保证有据可查）
- FR-2.3：支持停用耗材（逻辑删除）：停用后不出现在领用下拉框与补货巡检范围，历史流水保留可查；允许带库存停用，库存保留只读，系统提示"建议先盘点"
- FR-2.4：支持至少 5 种耗材录入；初始化预置焊丝、砂纸、记号笔、电阻、实训导线 5 条演示数据（含示例安全库存线，按真实调研替换）
- FR-2.5：档案列表展示：名称、规格、单位、存放位置、当前库存、安全库存线、状态、安全库存状态标识
- FR-2.6：数据表（`consumables`）：`id`、`name`、`spec`、`unit`、`location`、`safety_stock`、`current_stock`、`class_id`、`status`、`created_at`、`updated_at`

### FR-3 领用登记模块

- FR-3.1：领用表单支持**批量多行**（一次最多 5 行），每行包含：耗材选择（下拉框，展示"名称规格 + 当前库存"）、领用数量（正整数）；全表单共用领用人、领用时间
- FR-3.2：领用人从系统用户列表选择；学生角色锁定为本人；教师/班委可代填任意启用用户。领用时间默认当前时间，**可选过去 30 天内任意日期与时间（精确到分钟），禁止未来时间**
- FR-3.3：提交前置校验：每行数量必填且为正整数；耗材必须启用；每行数量 ≤ 当前库存。**任一行校验失败则整单拒绝**，返回明确错误并高亮对应行（如"库存不足：砂纸当前仅剩 3 张"），库存不变
- FR-3.4：校验通过后在一个数据库事务内完成：逐行原子扣减库存 + 生成对应领用流水；全部成功或全部回滚，严禁部分扣减
- FR-3.5：提交成功后页面即时反馈：领用成功、本次行数、每行扣减后剩余库存
- FR-3.6：领用流水字段（`requisitions`）：`id`、`consumable_id`、`user_id`、`quantity`、`stock_after`（领后剩余快照）、`type`（领用/红冲）、`status`（有效/已撤销）、`reversal_of`（红冲关联的原流水 ID）、`reversal_reason`、`class_id`、`created_at`、`remark`
- FR-3.7：并发安全：库存扣减须使用行级锁或条件原子更新（如 `UPDATE ... SET current_stock = current_stock - ? WHERE id = ? AND current_stock >= ?`），保证不超卖
- FR-3.8：提交按钮须防重复点击（提交中禁用），避免重复生成流水
- FR-3.9：**撤销领用（红冲）**：教师/班委可对"有效"的领用流水执行撤销；撤销在同一事务内完成：库存加回、原流水状态置为"已撤销"、生成一条类型为"红冲"的关联流水（数量等于原领用数量）；不删除、不编辑原流水
- FR-3.10：撤销原因必填，写入红冲流水与操作日志；撤销不设时间窗口限制
- FR-3.11：已撤销的流水不可再次撤销；红冲流水本身不可被撤销

### FR-4 库存总览页面

- FR-4.1：页面以表格展示全部启用耗材：名称、规格、存放位置、当前库存、安全库存线、状态标签；安全库存线对学生角色同样可见
- FR-4.2：当前库存低于安全库存线的条目以醒目样式标记（如红色行/红色标签"低库存"），并默认置顶排序，便于快速识别
- FR-4.3：页面顶部提供汇总指标卡片：**耗材总类数、低库存预警数、今日领用笔数**（今日新增的有效领用流水条数；不做跨单位"总量"求和）
- FR-4.4：任何领用/撤销/入库操作成功后，总览数据在刷新页面或轮询（30 秒）后即时反映最新库存
- FR-4.5：提供手动刷新按钮；库存为 0 的耗材额外标记"缺货"
- FR-4.6：学生角色可见总览页面，但看不到补货建议入口

### FR-5 领用记录查询

- FR-5.1：支持按耗材（下拉选择）、时间范围（起止日期）、领用人（教师/班委可查全部并可按人筛选）、流水状态（全部/有效/已撤销/红冲）组合查询
- FR-5.2：列表按领用时间倒序分页展示（默认每页 20 条），字段包含：领用时间、耗材名称规格、数量、领用人、领后剩余、状态（有效/已撤销/红冲）、备注；红冲流水以独立样式区分并关联显示原流水
- FR-5.3：学生角色只能查询本人流水，接口层强制过滤 `user_id`，防止越权查看他人记录
- FR-5.4：查询结果支持导出为 CSV（教师/班委可用，UTF-8 BOM 避免 Excel 乱码）
- FR-5.5：可追溯性要求：任意一条流水的"领后剩余"必须与库存变动一一对应；结合操作日志可反推任一时点的库存
- FR-5.6：消耗统计与 Agent 计算统一使用**净消耗**口径（窗口内领用数量 − 红冲数量，负值截断为 0）

### FR-6 智能补货 Agent（核心亮点）

Agent 采用"规则引擎计算 + 大模型润色"的两段式实现：规则引擎保证分级结果确定、可复现；大模型负责把数据事实润色为自然语言判断依据；大模型不可用时自动降级为规则模板文案。

**FR-6.1 巡检输入与分级规则（Agent 五步工作流）：**

1. **数据读取**：读取全部启用耗材的当前库存 C、安全库存线 S，以及近 7 天与再往前 7 天的流水
2. **指标计算**（净消耗口径）：
   - 库存缺口 G = max(S − C, 0)
   - 近 7 天净消耗 Q7 = Σ（近 7 天领用数量 − 近 7 天红冲数量），负值截断为 0
   - 日均消耗速率 r = Q7 ÷ 7（保留 2 位小数）
   - 可支撑天数 D = r > 0 ? C ÷ r : +∞（保留 1 位小数）
3. **三级分级**（按"紧急 → 一般 → 观察"顺序判定，首个命中的档位即为结果）：
   - **紧急**：C = 0，或 D ≤ 1 天，或 C < S × 30%
   - **一般**：C < S 且 D ≤ 3 天
   - **观察**：C < S 且 D > 3 天；或 C ≥ S 但近 7 天净消耗较前 7 天上升 ≥ 50%（趋势预警）
   - **正常**：其余情况，不输出补货建议
   - 边界规则：S = 0 的耗材不参与巡检；前 7 天净消耗为 0 而近 7 天 > 0 时视为趋势上升
4. **建议补货量计算**：R = ⌈G + r × 7⌉（补足安全库存缺口并覆盖未来 7 天消耗），覆盖天数固定为 7 天，不做配置项；r = 0 且 G > 0 时 R = G；观察档因趋势触发（C ≥ S）时 R = ⌈r × 7⌉；R 按最小单位向上取整，不引入包装规格
5. **建议生成与展示**：输出结构化建议卡片（见 FR-6.3），紧急级置顶

**FR-6.2 大模型润色规则：**

- 输入：耗材名称、当前库存、安全库存、近 7 天净消耗、日耗速率、可支撑天数、分级结果、建议补货量
- 输出：2–4 句中文判断依据，须引用输入中的具体数字，不得编造输入中不存在的数据
- 调用范围：**仅对紧急/一般/观察档耗材调用大模型**，正常档不调用（控制成本与延迟）
- 超时控制：单次调用超时 3 秒，超时或接口异常时立即回退为规则模板文案（如"当前库存低于安全库存 5 件，近 7 天净消耗 8 件（日均 1.14 件），仅可支撑 4.4 天，建议补货 13 件"）
- 供应商：默认 DeepSeek API（OpenAI 兼容 SDK），经适配层可切换华为云盘古；密钥通过环境变量注入，严禁硬编码进仓库
- 调用日志：记录每次 LLM 调用的耗时与成功/失败状态，便于演示说明与排查

**FR-6.3 建议卡片字段：** 耗材名称规格、当前库存、安全库存线、近 7 天净消耗、日均速率、可支撑天数、紧急程度（紧急/一般/观察，红/黄/蓝三色标签）、建议补货量、判断依据、生成时间。

**FR-6.4 巡检触发与缓存：** 打开补货建议页面时自动执行一次；提供"重新巡检"按钮手动触发；巡检结果按耗材缓存 10 分钟；**不保存历史巡检快照**（判断依据当场生成展示，处置动作与日志留痕）。

**FR-6.5 建议处置即入库：** 班委处置建议时须填写实际入库数量（正整数），备注选填；在同一事务内完成：增加当前库存、写操作日志（含变更前后值）、标记建议已处置；处置后建议从待处理列表移除。**建议处置是补货入库的唯一入口**，系统不存在其他直接改库存的路径。

### FR-7 近期消耗汇总

- FR-7.1：按耗材统计近 7 天（含当日）**净消耗**（领用 − 红冲，负值截断为 0），展示为表格 + 柱状图（ECharts 5 按需引入）
- FR-7.2：汇总数据必须直接来源于流水表聚合查询，与 FR-5 查询口径一致，禁止另设手工录入的统计数
- FR-7.3：支持切换时间窗口（近 7 天 / 近 30 天），供教师判断消耗趋势
- FR-7.4：页面同时展示每种耗材的日均消耗速率，与 Agent 计算口径完全一致

### FR-8 操作日志溯源

- FR-8.1：系统记录以下写操作：登录/退出、领用登记（含批量）、撤销领用（含原因）、耗材档案新增/修改/停用、安全库存线变更、建议处置（补货入库）；读操作不记录
- FR-8.2：日志字段（`operation_logs`）：操作时间、操作人、角色、操作类型、操作对象（耗材/建议/用户）、变更前后值（如库存 20 → 17）、备注
- FR-8.3：日志列表支持按操作类型、时间范围、操作人筛选，仅教师/班委可见
- FR-8.4：库存变动与流水/日志一一对应：任一库存变更必须能在领用流水（领用/红冲）或操作日志（补货入库）中找到来源

## 7. 关键流程 / 交互说明

### 7.1 角色登录与权限流程

1. 用户打开系统，未登录统一跳转登录页
2. 输入账号密码 → 后端 bcrypt 校验 → 签发 JWT 并写入 httpOnly Cookie（SameSite=Lax，8 小时）
3. 前端根据角色加载菜单：学生看不到档案管理、用户管理、补货建议、操作日志入口
4. 每次接口请求自动携带 Cookie → 后端鉴权依赖校验角色 → 越权返回 403
5. 退出登录清除 Cookie

### 7.2 批量领用流程（含撤销与异常分支）

1. 用户打开"领用登记"，表单默认为 1 行，可添加至最多 5 行；下拉框显示各耗材当前库存
2. 选择耗材与数量（学生领用人锁定本人；教师/班委可代选用户），确认领用时间（默认当前，可选过去 30 天内）
3. 点击"提交领用"
4. 后端逐行校验：耗材启用？数量为正整数？数量 ≤ 当前库存？
   - 任一行失败 → 整单拒绝，返回具体行与原因（如"第 2 行：砂纸库存不足，仅剩 3 张"），库存不变
   - 全部通过 → 事务内逐行条件扣减库存并写入流水 → 提交事务
5. 前端展示"领用成功：2 项，焊丝剩余 18 卷，砂纸剩余 12 张"
6. 需要纠错时：教师/班委在记录页对目标流水执行"撤销"→ 填写原因 → 库存加回、原流水标记已撤销、生成红冲流水

### 7.3 智能补货巡检与处置流程（闭环）

1. **数据读取**：Agent 拉取全部启用耗材库存与近 14 天流水
2. **指标计算**：净消耗口径计算缺口、日均速率、可支撑天数
3. **规则分级**：按"紧急→一般→观察"顺序输出分级（S=0 跳过，趋势规则生效）
4. **LLM 润色**：仅对非正常档调用大模型生成判断依据；3 秒超时降级为规则模板
5. **卡片展示**：按紧急程度排序展示建议卡片；班委点击"处置"→ 填写实际入库数量 → 事务内加库存、写日志、标记已处置

### 7.4 低库存预警展示流程

1. 教师/班委打开库存总览
2. 系统加载全部启用耗材，对比当前库存与安全库存线
3. 低于安全库存的条目红色标记并置顶；库存为 0 标记"缺货"
4. 页面顶部卡片展示耗材总类数、低库存预警数、今日领用笔数；教师可一键跳转补货建议页查看 Agent 建议

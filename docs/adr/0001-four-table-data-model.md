# 数据模型采用四张业务表

方案文档与架构图只定义了"耗材表 + 领用记录表"两张表，但多角色登录（教师/班委/学生）与操作日志溯源两项验收要求无法由两张表支撑。我们决定落库四张表：`users`（账号、密码哈希、角色、班级）、`consumables`（档案、当前库存、安全库存线）、`requisitions`（领用流水，含领后剩余快照与撤销标记）、`operation_logs`（只增不改的审计记录）。

**Considered Options**: 把用户写在配置文件（FR-1 无法完整验收）、日志只写应用日志文件（FR-8 无法验收）。坚持方案原文的两张表意味着放弃两个核心卖点，否决。

**Consequences**: 数据库初始化脚本需建四张表并预置三个演示账号；"库存变动可追溯"以 `requisitions` + `operation_logs` 双表为证据链。

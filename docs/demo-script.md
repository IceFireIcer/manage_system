## 1. 演示数据一览

执行 `python scripts/seed_demo.py` 后（班级 `class_id=1`）：

| 耗材 | 当前库存 | 安全线 S | 近 7 天净消耗 Q7 | 前 7 天 Qprev7 | 巡检档位 | 建议补货量 R |
| ---- | -------- | -------- | ---------------- | ------------- | -------- | ------------ |
| 焊丝（φ1.0mm，卷） | 1 | 5 | 8 | 4 | 紧急 | 12 |
| 记号笔（黑色，支） | 3 | 8 | 7 | 2 | 一般 | 12 |
| 电阻（10kΩ 1/4W，个） | 250 | 200 | 100 | 40 | 观察（趋势） | 100 |
| 砂纸（240目，张） | 50 | 20 | 0 | 0 | 正常 | — |
| 实训导线（1mm² 红，根） | 100 | 40 | 0 | 0 | 正常 | — |

判断依据（严格按 SPEC 顺序判定）：

- 焊丝：`C=1 < S×30%=1.5`，且 `C×7=7 ≤ Q7=8` → 紧急；`R=ceil(G + r×7)=ceil(4+8)=12`
- 记号笔：非紧急（`3×10 ≥ 8×3`），且 `C<S`、`C×7=21 ≤ 3×Q7=21` → 一般；`R=ceil(5+7)=12`
- 电阻：`C≥S`，且 `2×Q7=200 ≥ 3×Qprev7=120` → 观察（趋势）；`R=ceil(r×7)=100`
- 砂纸、实训导线：`C≥S` 且近 7 天无用量 → 不产生建议

历史流水共 20 笔，分布在近 30 天内，领用人轮换 `student01 / teacher01 / admin01`，用于记录查询与消耗汇总 7/30 天切换。7 天净消耗合计 115，30 天合计 181。

> 记号笔采用 3 支 / Q7=7 的校准值：若按 2 支 / Q7=3 会命中“紧急”而非“一般”。演示数字以本表为准。

- 在“补货建议”页点一次“重新巡检”：焊丝因趋势（Q7=8 ≥ 1.5×Qprev7=4）仍会以“观察”档出现，说明补货后趋势预警继续有效，直到高用量滚出 7 天窗口。
- 在“消耗汇总”页演示 7 天 / 30 天切换，说明撤销后净消耗不会被重复计入。

## 4. 录制建议

- 工具：OBS Studio 或 Windows 自带录屏（`Win + G`）；输出 1920×1080、30 fps，码率 6 Mbps 以上
- 画面：浏览器全屏（F11），缩放 100%；终端窗口字号 16 以上，只保留后端与前端两个进程
- 节奏：鼠标移动放慢，点击前停顿 0.3 秒；旁白按分镜表控制在 3 分钟内，语速平稳
- 音频：使用耳麦，提前测试音量；关闭微信/系统通知与输入法候选框
- 文件：录制完成后命名 `演示视频_班级实训耗材管理系统_T11.mp4`，与本文档、验收清单一起归档

## 5. 故障兜底

| 现象 | 处理 |
| ---- | ---- |
| DeepSeek 超时或无 Key | 无需处理，适配层自动降级为规则模板，卡片与数字不变 |
| 端口 8000 / 5173 被占用 | 后端改用 `uvicorn app.main:app --port 8001`，前端 `npm run dev -- --port 5174`（同步修改代理） |
| 建议页为空 | 检查是否在空库上漏跑 seed；执行 `python scripts/seed_demo.py` 后点“重新巡检” |
| 演示中误操作 | 用“撤销”纠正领用；或停止后端、删除 `backend/dev.db` 后重新 `alembic upgrade head` + `python scripts/seed_demo.py` |
| 云端不可用 | 切换本地零 Docker 启动脚本，演示内容完全一致 |

## 6. 演示后重置

若需把演示库恢复到初始三级场景：

```bash
cd backend
rm -f dev.db
alembic upgrade head
python scripts/seed_demo.py
```

脚本幂等：在已有演示流水的库上重跑会直接跳过，不会重复插入流水或重复扣库存。
